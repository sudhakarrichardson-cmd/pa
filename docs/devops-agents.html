📡
Production Monitor Agent
Triggered by merge · deploys to prod · watches rollout · closes issue
on: merge to main GitHub Actions + prod k8s
Agent instructs: kubectl set image …:new-tag
k8s executes: rolling update — new pod readinessProbe must pass before old pod dies
Agent watches: kubectl rollout status --timeout=3m
On failure: Agent calls kubectl rollout undo → k8s restores previous ReplicaSet
Closes issue · posts deploy summary to Telegram
Issue Status Lifecycle
open → analyzing → approved → in_dev → testing → passed → deploying → closed
Agent vs Kubernetes — who does what
🤖 Production Monitor Agent (brain)
1
Decides when to deploy (merge event)
2
Runs kubectl set image …:new-tag
3
Watches rollout status --timeout=3m
4
On failure: runs kubectl rollout undo
5
Posts result to Telegram, closes issue
⚙️ Kubernetes (hands)
1
Executes rolling update (new pod first)
2
Runs readinessProbe on each new pod
3
Only kills old pod after new one is ready
4
On rollout undo: restores previous ReplicaSet
5
Zero-downtime guaranteed by design
